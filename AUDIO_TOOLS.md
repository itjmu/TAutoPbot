# Audio preparation

The main menu's **✍️ Аудио** replaces only the main Conditions shortcut. It immediately requests one audio file or voice message; no channel, post, publication controls or post-creation allowance is involved. Existing Conditions entry points remain available. Channel/group condition cards can create and assign a condition directly to that destination, with ownership checks; request approval is not automatically enabled.

Send a file, change the desired settings, then select **Get file** to receive the prepared media in the private chat. Use ordinary Autoposting separately if publication is wanted. The resulting file is retained when returning home. Settings use the existing FSM, so leaving the workflow or restarting loses the editing session; the original incoming message and already returned files remain available. Session tokens reject old callbacks.

Available tools:

- MP3/M4A: title, performer, album, year, genre, filename, embedded cover addition/removal and caption.
- Output choices: MP3, M4A/AAC, OGG/Opus, FLAC and WAV. The current format is hidden; OGA/OPUS extensions are treated as OGG aliases. Choosing a format only saves settings. Preparation starts only after Get file. MP3/M4A can be delivered as music or voice without re-encoding just to change presentation; OGG is voice, FLAC/WAV are files. Existing input formats remain accepted.
- Trimming was removed from the standalone Audio menu. Compatible legacy draft processing and pending earlier trim settings remain supported.
- Embed or remove up to 10000 characters of unsynchronized lyrics in standard MP3 USLT / M4A ©lyr tags using Mutagen. Compatible phone music players can display them; Telegram is not promised to show a lyrics panel.
- Replace the source, reset to the original, or receive the current version again.

Accepted extensions: MP3, M4A, OGG, OGA, OPUS, WAV, FLAC, AAC, WMA, AIFF. Input and prepared output are limited to 20 MiB, matching the existing hosted Telegram download boundary. Unknown input sizes are rejected. Covers accept photos or PNG/JPEG documents up to 2 MiB, resized to a JPEG thumbnail within Telegram's limits.

Standalone conversions accept recordings up to 10 minutes (container headers validate actual duration); ordinary legacy draft conversion remains limited to 120 seconds. Tag/cover edits preserve encoded audio. MP3/M4A use 128 kbps, OGG/Opus uses mono 48 kbps, and FLAC/WAV use stereo 48 kHz (WAV 16-bit). WAV is rejected before encoding when its estimated size exceeds 20 MiB. FLAC/WAV output caps are checked for size and duration so an oversized recording is never silently delivered shortened. These formats do not restore quality lost in a compressed source. Covers and lyrics are exposed for MP3/M4A; incompatible pending cover/lyrics settings produce a clear error and remain available for correction.

Preparation runs as a supervised background job. Its progress message shows download/edit/upload phases and upload byte percentages, with Stop and Main menu buttons. Leaving for the main menu does not cancel preparation or reopen the editor when it finishes. Processing, downloads and upload share a 300-second deadline. Cancellation kills the FFmpeg process and temporary files are cleaned. One job per user and two simultaneous audio jobs are permitted; the standalone flow rejects a busy global pool instead of waiting in a queue. Telegram/network speed cannot be guaranteed, and a timed-out upload can have an uncertain delivery outcome. Failures retain the source and pending settings. Legacy audio post drafts/callbacks retain their existing workflow and 20 MiB processing limit.

Implementation: `app/features/audio_utility.py`, compatible draft tools in `app/features/audio.py`, and `services/audio_files.py`. Additive `posts.audio_meta_json` stores ordinary post audio metadata and prepared IDs. Ordinary post rendering preserves title/performer and caches prepared media without replacing the draft's source file ID. English and Kazakh UI translations are included.

Verification includes mocked Telegram/FSM/ownership/limits/error/background-navigation tests and real local FFmpeg/Mutagen lyrics, tag, embedded-cover, encoded-packet preservation, all five output formats, voice/music/file delivery and size checks. Latest full suite: 293 offline tests passed in 42.160 seconds, recorded in `audio_download_speed_tests.log`. Telegram delivery is mocked. No live Telegram actions, production migration, restart or deployment were performed.

Autoposting now uses Next to open the final preview and publication controls: Schedule, Auto-delete, copy protection and notification sound, plus Back/Publish. Muting maps to Telegram `disable_notification`: the notification is silent, not suppressed. The flag is persisted additively on posts and travels through immediate/scheduled media and album delivery. Existing publish callbacks remain compatible. Published-message editing has no copy-protection control, because that operation is unsupported. Draft protection remains available. The edit screen places Back / Pin / Next together.

Audio downloads retry once for transient network errors, using a fresh bounded buffer. File-location lookup has a 30-second limit; each transfer has a 120-second limit within the 300-second job deadline. Download progress reports actual buffered bytes, with 256 KiB transfer chunks. Cancellation awaits transfer cleanup before closing the bounded buffer. Validation, processing and upload errors are not retried. Failure progress shows the stage and sanitized reason; sources and settings are retained. Unchanged media/results reuse Telegram file IDs without source download. The earlier live network stall remains unconfirmed; longer timeouts do not themselves improve transfer speed.
